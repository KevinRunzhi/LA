## 2. 系统能演示什么

主案例：山东德州分输站站控柜 A01，研华 ACP-4000 / IPC-610 工控机 TEMP/FAN 告警及散热异常。

完整主线：

> 工程师描述异常 → 动态接诊 → 辅助诊断 → 编辑并确认检修方案 → 图文向导 → 恢复验证 → 记录与作业卡 → 专家审核 → 知识发布 → 工程师同步。

| 模块 | 当前实现与演示边界 |
| --- | --- |
| 工程师工作台 | 动态接诊、场站图、诊断、方案编辑、逐步检修与记录 |
| 检修智能体 | 预置内容、步骤相关问答和流式动画；没有真实大模型推理 |
| 媒体、语音与视频协同 | 演示交互；媒体主要为当前浏览器预览，不提供完整上传持久化与真实识别 |
| 作业卡 | 两页打印视图，可由浏览器选择保存为 PDF |
| 专家门户 | 案例审核、修正知识和图谱、发布知识 |
| 工程师知识同步 | SQLite 保存发布版本及工程师本地知识快照 |
| 管理员门户 | 用户管理演示界面；登录和角色选择不构成生产鉴权 |
| 案例范围 | 一个完整散热闭环；其他案例主要为只读摘要或资料 |

本版不包含后来新增的 CaseRun 平台、案例发布中心、资料驱动案例生成或生产运维后台。旧设计中的 Vue、FastAPI、PostgreSQL、pgvector、Neo4j 等属于目标方案，本版实际采用 React、Vite、Flask、SQLite 和本地文件。

系统使用预设现场读数及处理结果。手册依据、预设现场数据和真实维修证据应区分，不应将本版说成已经完成现场工业验证。

## 3. 运行结构与代码入口

运行时，浏览器呈现 React 页面，Flask 提供演示 API；构建后的页面也可直接由 Flask 托管。JSON 提供场景与重置种子，SQLite 保存审核、知识发布和同步状态。

| 路径 | 接手时主要看什么 |
| --- | --- |
| `frontend/src/App.jsx` | 工程师主流程、状态、方案、向导、记录和问答 |
| `frontend/src/styles/` | 页面、流式展示、语音与打印样式 |
| `frontend/src/components/` | 聊天呈现、语音、专家协同及作业卡组件 |
| `frontend/src/admin/AdminShell.jsx` | 专家门户和审核发布 |
| `frontend/src/admin/AdminUserPortal.jsx` | 管理员演示门户 |
| `frontend/src/admin/knowledge-graph/` | 全局与变更知识图谱 |
| `frontend/src/api/client.js` | 主流程 API 和部分离线兜底 |
| `frontend/src/admin/presentationApi.js` | 审核、知识、图谱及同步 API |
| `backend/app.py` | Flask 路由、场景装载、手册文件服务和静态托管 |
| `backend/presentation_store.py` | SQLite 初始化、审核发布、版本和同步 |
| `backend/data/*.json` | 场景、五步向导、知识与图谱预置内容 |
| `backend/data/presentation/` | 完整案例、知识、手册目录、图谱及初始状态 |
| `Info/` | 登记的厂商手册及说明材料，部署时需保留 |
| `deploy/loongarch/scripts/` | 环境检查、安装、后台启停、健康检查及演示复位 |
| `scripts/package-loongarch-stable.sh` | 构建并生成带静态页面和手册的演示部署包 |

资料目录中的手册由 `manual_sources.json` 引用。只复制前后端两个目录会导致部分资料页面缺文件；优先获取完整源码或使用仓库自带的部署打包脚本。

## 5. 建议按这个顺序演示

首次启动已是种子状态；若此前跑过演示，先按部署文档备份需要保留的数据，再重置。

### 工程师阶段

1. 选择工程师身份登录。
2. 输入：“站控柜内工控机温度告警，风扇声音异常，前面板风扇转速很低。”
3. 开始接诊，确认发生时间、地点、设备与异常、运行参数和依据资料。
4. 查看场站图与右侧 Agent 输出，完成多 Agent 会诊展示。
5. 查看诊断结论，进入可编辑检修预方案；可演示普通步骤的修改，保留必要安全项。
6. 确认方案，逐步完成告警确认、安全准备、环境风道、滤网风扇接线、恢复验证。
7. 生成检修完成记录，查看处理前后读数和两页作业卡。
8. 点击“上传至专家知识库”，退出工程师入口。

### 专家阶段

1. 选择专家身份登录，打开 `CASE-ACP4000-001`。
2. 检查工程师记录，修正案例结论、知识和图谱关系。
3. 按界面三步完成审核与发布；主要动态知识为 `KB-008`，版本从 V1.0 变为 V1.1。
4. 在全局图谱与“本次新增与修改”中查看变化，退出专家入口。

### 工程师同步与管理员展示

1. 再进入工程师入口，确认有可同步知识，完成同步。
2. 查看新版本及图谱变化，演示相似异常问答或回流验证。
3. 如需展示管理员，最后单独切换管理员身份查看用户管理界面。

每一步应看到对应页面或状态再继续；Agent 动画有等待时间。知识发布与同步依赖后端，只启动前端无法完成全部演示。

## 6. 数据、备份和接手注意事项

- 数据库为 `backend/data/presentation/presentation.db`，首次启动自动生成；不会随 Git 克隆获得已有演示进度。
- JSON 是预置资料和重置种子，不能替代 SQLite 的动态状态。
- 只刷新浏览器不会重置知识版本；部分接诊、方案和向导状态则只在前端会话中。
- 不把其他版本的运行数据库直接覆盖到本版；跨版本数据库兼容性未验证。
- 图片、视频、音频主要在当前浏览器会话预览，不能承诺服务器已完整归档。
- 旧后端测试会操作当前目录的演示数据库。需要保留记录时，先备份或使用独立验证副本。
- 多人同时演示会共享全局案例状态；建议一名操作者按顺序演示。

具体备份、恢复、重置和启停命令见 [部署文档](deployment.md)。
