## 编写定位与统一口径

本文档面向最终参赛交付版本，回答“如何取得、校验、安装、配置、初始化、启动、验证、维护、备份、升级、回退和卸载软件”。正式正文以目标技术架构为唯一主线，不以当前 React、Flask、SQLite/JSON 演示包替代最终交付形态。

最终软件采用 B/S 架构，以 LoongArch64 离线安装包作为正式交付载体。安装包应随包提供前端生产构建、Python 运行环境及离线依赖、FastAPI 核心业务服务、Celery 工作进程、Nginx、PostgreSQL、pgvector、Redis、Neo4j、文件资源库、PDF 与多媒体处理依赖、Prometheus、Grafana、数据库迁移与初始化脚本、systemd 服务配置、默认配置模板、必要字体和完整卸载维护脚本。安装过程不得依赖临时访问外部软件源。

千问语言、OCR、ASR、向量化和重排序能力通过统一模型网关接入。安装包随包部署模型网关、调用适配器、配置模板和联通性检查工具；模型权重或云端 API 本身是否本地随包交付，按照最终比赛网络与算力方案说明，不得把外部模型服务写成本机已安装组件。

Neo4j 产品选型保持不变。安装包应包含相应部署资源和初始化内容；其运行位置根据 LoongArch64 专项验证结果支持“业务节点原生部署”或“独立兼容节点部署”两种拓扑，正文分别给出操作步骤，不在验证完成前虚构原生兼容结论。

## 2. 最终交付物与部署方案

### 2.1 正式交付物清单

说明交付介质至少包含：

- LoongArch64 主离线安装包；
- 安装包 SHA-256 校验文件；
- 离线系统软件包与 Python 依赖仓；
- 前端生产构建与后端应用包；
- PostgreSQL、pgvector、Redis、Neo4j、Nginx、Prometheus、Grafana 的离线部署资源；
- 数据库迁移、基础数据、知识数据和图谱初始化资源；
- systemd、Nginx、监控、日志轮转和备份配置模板；
- 思源黑体、思源宋体等 PDF 中文字体资源；
- 安装、检查、启动、停止、重启、备份、恢复、升级、回退和卸载脚本；
- 软件安装包及部署文档、版本说明和第三方组件许可证清单。

### 2.2 目标部署拓扑

以图示说明以下节点关系：

1. **LoongArch64 业务节点**：Nginx、Vue 前端、FastAPI/Uvicorn、Celery、Redis、PostgreSQL/pgvector、文件资源库、FFmpeg、WeasyPrint、Prometheus、Grafana和systemd服务；
2. **图数据库节点**：Neo4j，可根据兼容性验证部署于业务节点或独立兼容节点；
3. **模型推理节点或模型 API**：语言、视觉、OCR、ASR、向量化和重排序能力，通过统一模型网关接入；
4. **用户访问端**：工程师、专家和用户管理员通过浏览器访问 Nginx 统一入口。

### 2.3 单节点部署方案

说明在资源满足且组件兼容性验证通过时，除外部模型能力外的全部业务组件在一台 LoongArch64 节点运行的安装顺序、资源边界和适用场景。

### 2.4 多节点部署方案

说明 Neo4j 或模型推理服务部署在独立节点时的网络、证书、账号、端口、连接配置、时间同步和故障隔离要求。

### 2.5 组件依赖关系与启动顺序

明确启动链路：基础目录与秘密配置 → PostgreSQL/pgvector、Redis、Neo4j → 数据迁移与初始化 → FastAPI → Celery → Nginx → Prometheus/Grafana → 综合健康检查。

### 2.6 部署边界

明确正式包是目标架构的完整离线交付包；开发环境、源码热更新和当前演示包只作为研发参考，不纳入正式部署主流程。

## 5. 部署前准备与环境检查

### 5.1 获取并核对交付介质

核对主安装包、校验文件、组件清单、许可证、部署文档和可选节点安装包是否齐全。

### 5.2 记录目标环境

采集 CPU 架构、操作系统、内核、内存、磁盘、Java、端口、网络、时间和已有服务信息，形成部署前环境快照。

### 5.3 检查旧版本和端口占用

识别旧服务、旧数据库和旧部署目录，优先使用旧版本自己的停止脚本，禁止批量终止来源不明的进程。

对旧版本 PostgreSQL、Neo4j、文件资源库、配置和证书形成同批次备份，并验证备份可读。

### 5.5 安装介质完整性检查

执行 SHA-256、文件数量、架构、组件版本和第三方许可证核对；失败时停止部署。

### 5.6 环境检查脚本

运行随包环境检查，验证系统版本、架构、资源、目录、端口、时间、依赖兼容性和节点连通性，输出通过、警告和失败清单。

### 5.7 部署前检查表

汇总安装介质、硬件、操作系统、权限、磁盘、端口、备份、秘密配置、证书和模型服务条件。

## 7. 基础组件离线安装

### 7.1 安装顺序与原则

统一说明所有依赖从随包离线仓安装，不访问外部系统软件源，不修改无关系统组件。

### 7.2 Python 3.12 与离线依赖

安装或使用随包 Python 运行环境，创建项目虚拟环境，从本地 wheel 仓安装 FastAPI、Pydantic、SQLAlchemy、Alembic、Celery、模型客户端、文档解析、PDF 及其他固定依赖。

### 7.3 Nginx

安装 LoongArch64 适配版本，部署前端静态资源、反向代理、TLS、请求体限制、安全响应头和访问日志配置。

### 7.4 PostgreSQL

安装固定版本，创建数据目录和 systemd 服务，设置本机或受控地址监听、认证规则、字符集、时区和资源参数。

### 7.5 pgvector

安装与 PostgreSQL 版本匹配的 LoongArch64 扩展，验证 `CREATE EXTENSION vector`、1024 维向量字段和相似度查询。

### 7.6 Redis

安装固定版本，限制监听地址，配置身份保护、持久化策略、内存上限和 systemd 服务，禁止外部直接访问。

### 7.7 Neo4j

按照最终验证结果选择：

- LoongArch64 业务节点原生安装；或
- 独立兼容节点安装。

两种方式均说明 OpenJDK、目录、端口、认证、Bolt、内存、许可证、备份工具和连通性检查。

### 7.8 FFmpeg、WeasyPrint 与字体

安装音视频转换、PDF 渲染和中文字体依赖，验证 FFmpeg 编解码能力及两页 A4 中文作业卡生成。

### 7.9 Prometheus 与 Grafana

安装目标平台适配版本，创建服务账号、数据目录和 systemd 服务，限制管理入口访问范围。

### 7.10 基础组件安装验证

逐项检查版本、架构、进程、端口、日志和最小读写能力，任何关键组件失败时不进入应用初始化。

## 8. 应用安装与配置

### 8.1 部署前端生产资源

复制 Vue/Vite 构建产物，配置 Nginx 静态资源缓存、历史路由回退、API/SSE 反向代理和文件访问规则。

### 8.2 部署 FastAPI 核心业务服务

安装应用代码或构建产物，配置 Uvicorn 工作参数、应用目录、运行账号、日志和健康接口。

### 8.3 部署 Celery 工作进程

配置队列、并发数、任务超时、重试、失败记录和临时目录，区分文档解析、OCR/ASR、向量化、PDF 和知识处理任务。

### 8.4 部署统一模型网关

配置语言、OCR、ASR、向量化和重排序模型的标准接口、超时、重试、限流和降级策略；密钥通过秘密配置注入。

### 8.5 部署文件资源库

创建原始手册、现场材料、解析中间件、导出文件和临时文件目录，配置访问权限、大小限制、校验值和清理策略。

### 8.6 部署 systemd 服务

安装核心业务、Celery、可选调度任务及相关服务单元，配置启动依赖、异常重启、资源限制和开机自启。

### 8.7 部署日志与轮转配置

配置 Nginx、应用、Celery、数据库、图数据库、Redis、监控和安装过程日志的路径、格式、保留和脱敏。

### 8.8 部署监控配置

导入 Prometheus 抓取目标、告警规则、Grafana 数据源和仪表盘，覆盖服务、接口、队列、数据库、主机资源、备份和安全事件。

## 9. 安全配置与秘密管理

### 9.1 配置文件层级

区分随包默认模板、环境配置、节点配置和秘密配置，说明优先级、文件权限和变更审计。

### 9.2 数据库与组件账号

创建业务、迁移、备份、监控和只读账号，分别授予 PostgreSQL、Neo4j 和 Redis 的最小权限。

### 9.3 JWT 与会话配置

生成 JWT 签名材料、会话密钥和 Cookie/CSRF 参数，不使用安装包内的默认生产密钥。

### 9.4 模型服务凭据

配置千问模型 API 地址、模型名称和密钥，禁止写入前端、代码、普通配置模板和日志。

### 9.5 TLS 与访问入口

配置证书、域名或受控 IP 访问、Nginx TLS、安全响应头、可信代理和请求限流。

### 9.6 网络访问控制

只开放 Nginx 统一入口；Uvicorn、PostgreSQL、Redis 和本机 Neo4j 仅监听受控地址，独立节点端口只向指定业务节点开放。

### 9.7 配置检查

使用检查脚本确认无默认密码、无明文密钥泄露、目录权限正确、配置项完整且节点地址可达。

## 10. 数据库、知识与图谱初始化

### 10.1 初始化顺序

按照 PostgreSQL 集群与账号 → pgvector 扩展 → Alembic 迁移 → 基础业务数据 → 文件资源 → 知识条目与向量 → Neo4j 模式与图数据 → 一致性校验执行。

### 10.2 PostgreSQL 数据库创建

创建业务数据库、字符集、时区、模式和扩展，使用专用迁移账号执行结构初始化。

### 10.3 Alembic 数据迁移

检查当前模式版本，执行升级，记录迁移前后版本；失败时回滚到迁移前备份或停止安装。

### 10.4 初始账号与组织数据

导入工程师、专家、用户管理员、组织和角色基础数据，首次登录必须修改临时口令或按照最终安全方案激活。

### 10.5 知识库与向量数据初始化

导入厂商手册、结构化知识、历史案例和来源信息，执行文档解析、分段、向量化与索引构建，记录失败项目。

### 10.6 Neo4j 模式与图数据初始化

创建约束、索引、节点和关系，验证稳定业务标识、来源、版本和发布状态。

### 10.7 文件资源初始化

复制并校验原始手册、模板、示例材料和字体资源，确保数据库元数据与实际文件一一对应。

### 10.8 跨存储一致性检查

检查 PostgreSQL、pgvector、Neo4j 和文件资源库中的业务标识、知识版本、图谱版本、文件校验值和发布批次一致。

### 10.9 初始化结果清单

输出数据库版本、数据数量、知识片段数、图谱节点关系数、文件数量、失败项和校验值。

## 11. 服务启动、停止与状态检查

### 11.1 启动前检查

确认配置、秘密、数据迁移、目录权限、端口和基础组件状态。

### 11.2 启动顺序

### 11.3 综合启动脚本

### 12.9 部署验收记录

## 15. 版本升级与回退

### 15.1 升级包组成

包含应用差异、完整组件要求、Alembic 迁移、知识与图谱迁移、配置变更说明、校验文件和回退资源。

### 15.2 升级前检查

验证当前版本、目标版本、磁盘、组件兼容性、备份完整性和维护窗口。

### 15.3 升级顺序

停止入口和任务接收、完成一致性备份、升级组件、部署应用、执行数据库迁移、更新知识与图谱、启动并验收。

### 15.4 配置迁移

保留用户秘密和现场参数，只合并已明确新增或变更的配置项，不以默认模板覆盖现有配置。

### 15.5 回退触发条件

包括组件无法启动、迁移失败、核心闭环阻断、数据不一致、性能严重退化和安全配置失败。

### 15.6 应用与数据回退

回退应用、PostgreSQL、Neo4j、文件资源和配置到同一备份批次，禁止只回退单一存储造成版本错配。

### 15.7 回退后验收

重新执行健康检查、跨存储一致性检查和核心业务路径，保留失败版本现场和日志。

## 正式正文编写原则

1. 以目标架构完整随包部署为主线，当前演示包不得替代正式交付方案。
2. 所有运行依赖均从离线安装介质获得，安装过程不得临时访问外部系统软件源。
3. 模型网关及适配器随包部署，外部模型 API 或独立推理节点按最终方案明确边界和网络条件。
4. Neo4j 必须纳入正式部署，但原生节点或独立兼容节点由专项验证结果决定，两套步骤均可保留。
5. PostgreSQL、pgvector、Neo4j 和文件资源库使用统一版本与备份批次，初始化、升级和回退必须保持跨存储一致。
6. 安装脚本必须支持环境检查、幂等执行、失败定位、安全重试和明确退出码，不静默跳过失败组件。
7. 删除、覆盖、停止服务、恢复和卸载操作必须先确认目标并保留可恢复路径。
8. 最终安装包名称、版本、组件清单、端口、配置、SHA-256 和验收结果必须与功能设计及测试报告一致。
