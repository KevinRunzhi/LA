# 工业设备智能检修系统功能演示视频脚本

## 1. 脚本说明

### 1.1 录制目标

本视频用于完整展示工业设备智能检修系统的核心业务能力。视频以一台工控机的散热异常为贯穿案例，按照“现场接入—智能诊断—检修执行—恢复验证—案例沉淀—专家审核—知识回流—后台管理”的顺序展开。

视频不是逐个菜单介绍，而是用一个真实业务闭环串联功能。其他设备型号和故障领域通过检修资料、历史案例、检修知识库和全局知识图谱集中展示。

### 1.2 时间与格式

- 成片时长：6 分 50 秒，必须控制在 7 分钟以内；
- 片头动画：10 秒；片尾动画：10 秒；两段动画原则上不安排口播；
- 片头 10 秒只承担项目名称和主视觉，不叠加大段项目背景；
- 全片口播以多 Agent 在资料收集、设备识别、异常研判、步骤生成和知识存储中的协同为核心，不展开与传统对话式大模型的比较；
- 建议格式：MP4，H.264 编码，1920×1080，30 fps；
- 画面比例：16:9；
- 录制方式：屏幕操作为主，后期配音；
- 节奏原则：重要状态变化保留完整操作，页面切换和等待动画可在后期加速至 1.5～2 倍；
- 角色顺序：工程师 → 专家 → 管理员。

### 1.3 一句话主线

> 系统把现场异常、检修资料、多智能体诊断、规范作业和专家知识维护连接成一个可追溯、可复用、持续更新的工业设备检修闭环。

## 3. 逐镜头录制脚本

## 镜头 01：片头动画

**时间：00:00—00:10**

### 画面操作

1. 以深色背景或系统主视觉作为首画面；
2. 片头动画依次出现：
   - 工业设备智能检修系统；
   - 面向油气场站工控设备的智能接诊与知识闭环；
3. 系统标识完成动态组合后，转场至登录页。

### 画面节奏与特写

- 前 3 秒建立主视觉，中间 5 秒完成标识和系统名称动画，最后 2 秒为转场；
- 字幕不超过两行，避免片头尚未结束就出现大量说明；
- 音乐由弱到强，在切入项目背景时降低音量，为第一句口播留出空间。

### 口播

本段不安排口播，只保留片头音乐和必要的动画音效。

### 画面验收

- 系统名称完整可见；
- 不出现开发工具、终端、浏览器书签和无关通知；
- 片头严格控制为 10 秒；
- 动画最后一帧能够自然衔接登录页。

## 镜头 02：项目背景、系统定位与工程师工作台

**时间：00:10—00:35**

### 画面操作

1. 00:10—00:20 使用场站全景、工控设备、告警信息和纸质手册组成项目背景画面；
2. 通过简洁字幕依次呈现“设备分散”“信息来源多”“检修依赖经验”“知识难沉淀”；
3. 画面中的告警、手册和历史记录汇聚到系统标识，转场至登录页；
4. 00:20—00:35 选择“工程师”，使用预置账号登录；
5. 进入工程师工作台，依次扫过当前任务、待处理异常、最近检修记录和检修资料入口。

### 画面节奏与特写

- 项目背景只说明问题，不展示大段文字，每个痛点字幕约出现 1.5 秒；
- 从背景画面转到登录页时，使用告警卡片收拢或数据线汇聚动画；
- 登录过程控制在 3 秒左右，密码区域通过裁切或加速处理；
- 工作台停留约 5 秒，让评委看清系统已经进入实际业务界面。

### 口播

> 油气场站工控设备分布广、运行连续，异常信息来自告警、现场现象和检修资料，传统处理较依赖个人经验，经验也难以持续沉淀。为此，我们建设了工业设备智能检修系统，将异常接入、智能诊断、规范作业、专家审核和知识更新连接为完整闭环。下面首先进入工程师工作台。

### 画面验收

- 角色选择明确；
- 项目背景能够说明现场痛点，但不超过 10 秒；
- 工程师工作台完整出现；
- 登录密码不得在成片中清晰展示。

## 镜头 03：选择检修资料并接入语音和现场材料

**时间：00:35—01:05**

### 前置状态

- 准备两张工控机或机柜现场图片；
- 检修资料选择状态已重置。

### 画面操作

1. 点击首页“检修资料”；
2. 在“检修资料编组台”中快速展示：
   - 历史案例；
   - 检修知识；
   - 厂商操作手册；
3. 选择以下三项资料并确认：
   - 工控机散热异常历史案例；
   - `KB-008` 散热与风扇检修知识；
   - 工控机厂商用户手册或维护手册；
4. 返回接入页面，展示由语音输入识别得到的异常描述；
5. 接入两张现场图片，画面出现已接入状态。

### 画面节奏与特写

- 先用全页面展示资料数量和分类，再对选中的三项资料做局部放大；
- 语音输入的中间过程不必保留，以识别后已回填的异常文字作为结果画面；
- 上传文件只保留点击前和接入成功后的画面，文件选择窗口不进入成片；
- 以资料和材料均处于已接入状态作为本镜头结束画面。

### 固定语音内容

> 站控柜 A01 工控机温度告警，风扇声音异常，设备仍在运行，请协助检修。

### 口播

> 工程师可先从历史案例、结构化知识和厂商手册中选择本次检修资料。系统同时支持文字、语音、图片、视频和音频接入，并将所选资料和现场材料持续关联到本次异常事件。

### 画面验收

- 资料被选中后有持续状态；
- 语音识别结果回填到异常描述；
- 两张图片均出现“已接入”或等价状态；
- 不要在文件选择窗口停留。

## 镜头 04：五步异常接入与信息确认

**时间：01:05—01:35**

### 画面操作

1. 启动异常接入；
2. 按页面顺序完成五个阶段，已预填内容只需核对并点击下一步；
3. 重点停留在设备告警和运行参数页面：
   - TEMP/FAN 告警；
   - 风扇转速 420 rpm；
   - 系统温度 58℃；
   - CPU 温度 74℃；
4. 在最终摘要页扫过现场、位置、设备、告警、参数和材料；
5. 点击“启动智能诊断”。

### 画面节奏与特写

- 前四个阶段使用快速连贯点击，每一步约停留 2～3 秒；
- 风扇转速、系统温度和 CPU 温度使用局部高亮，确保数值可读；
- 摘要页至少停留 5 秒，镜头按“位置—设备—告警—参数—材料”顺序移动；
- 点击“启动智能诊断”后保留按钮反馈，再转入智能体处理画面。

### 口播

> 系统通过分步接入引导工程师补齐时间、位置、设备、告警和运行状态，并自动形成结构化事件摘要。本次设备风扇仅为每分钟四百二十转，系统温度五十八度，CPU 温度七十四度，已满足散热异常的重点诊断条件。

### 画面验收

- 五步进度清晰可见；
- 最终摘要同时包含事实、材料和运行参数；
- “启动智能诊断”按钮点击过程完整保留。

## 镜头 05：多智能体协同诊断

**时间：01:35—02:05**

### 画面操作

1. 保留多智能体处理动画约 2 秒；
2. 依次突出以下智能体输出：
   - 设备识别；
   - 故障分析；
   - 安全合规；
   - 知识检索；
3. 展示综合诊断结论和引用依据；
4. 展开一条知识依据，显示来源手册或历史案例；
5. 如页面提供诊断追问，输入“为什么优先检查滤网和风扇？”并提交。

### 画面节奏与特写

- 多智能体处理动画保留约 2 秒，随后按角色输出顺序切换焦点；
- 每类智能体只突出一句核心结论，不逐字朗读全部内容；
- 展开依据时，将来源名称和关键页码放大，证明结论有出处；
- 最后停留在综合诊断结论和建议措施，为检修预案自然铺垫。

### 口播

> 接入完成后，设备识别、故障分析、安全合规和知识检索等智能体协同处理现场事实：分别完成设备确认、异常研判、操作约束和资料检索，再汇总生成可执行结果。后续检修步骤与现场经验也由 Agent 继续生成并存储，形成贯穿检修全流程的协作链路。

### 画面验收

- 至少三类智能体结果出现在同一段画面中；
- 诊断结论与证据来源同时可见；
- 不等待所有逐字动画自然播放，可在后期适当加速。

## 镜头 06：查看并确认可调整的检修预案

**时间：02:05—02:20**

### 画面操作

1. 进入检修预案页面；
2. 快速扫过五个步骤；
3. 展示步骤上移、下移、删除等调整入口；
4. 确认预案并进入检修向导。

### 画面节奏与特写

- 先以全景呈现五步大纲，再放大步骤调整入口；
- 通过“进入检修向导”按钮完成转场，让诊断建议自然进入执行阶段。

### 口播

> AI Agent 汇总诊断结论、知识检索结果和安全约束，以大纲形式自动生成检修预案。工程师可结合现场条件修改和调整步骤，确认后再进入检修向导。

### 画面验收

- 五步预案可见；
- 上移、下移或删除等调整入口可见；
- 确认后能够进入检修向导。

## 镜头 07：检修向导、当前步骤问答与语音播报

**时间：02:20—03:10**

### 画面操作

1. 进入检修向导；
2. 快速展示前 3 个步骤：
   - 确认告警与定位设备；
   - 执行安全准备；
   - 检查机柜环境与风道；
3. 在第 2 步短暂停留安全隔离和防静电提示；
4. 进入第 4 步“检查滤网、风扇和接线”；
5. 在右侧检修智能体中提问：
   - “这个接线顺序是怎么样的？”
6. 展示回答中的 FAN1/FAN2 核对顺序和断电要求；
7. 在第 2 步展示专家视频会诊入口、会诊界面和完成状态；
8. 在第 3 步展示语音播报状态；
9. 完成第 4 步并进入恢复验证。

### 画面节奏与特写

- 前三个步骤使用卡点快切，只让步骤标题和安全重点清晰出现；
- 各步骤中的设备图、风道图、滤网图和接口图应清晰出现，体现 Agent 根据知识库内容选择指导维修图片；
- 第四步保持中间作业区与右侧检修智能体同时可见，并整体倍速播放；
- 问答保留提问、资料检索、答案重点和依据来源，局部放大 FAN1/FAN2 关键内容；
- 专家会诊保留入口、会诊界面和完成状态；语音播报保留状态变化；
- 以第 4 步完成状态作为结束，避免直接跳到恢复数据造成流程断裂。

### 口播

> Agent 自动总结生成检修向导，并根据知识库内容为各步骤选择相应的指导维修图片。系统接入语音模型，可提供语音向导；遇到复杂问题，还能在当前步骤发起与专家的视频会诊。检修过程中如有任何疑问，工程师都可向检修智能体提问。这里以 FAN1/FAN2 接线顺序为例，Agent 综合设备信息、当前步骤和手册依据生成回答。

### 画面验收

- 当前步骤标题必须是“检查滤网、风扇和接线”；
- FAN1/FAN2 固定问题在该步骤内出现；
- 回答与当前步骤相关，不出现泛化答复；
- 语音播报状态有明显变化；
- 专家会诊窗口仅展示入口和界面，不消耗过多时间。

## 镜头 08：恢复验证与提交专家审核

**时间：03:10—03:35**

### 画面操作

1. 进入“恢复运行与验证”；
2. 填入固定恢复参数：
   - 风扇转速 1280 rpm；
   - 系统温度 42℃；
   - CPU 温度 58℃；
   - 连续观察 15 分钟；
3. 填入最终原因和实际处理；
4. 提交检修结果；
5. 展示“已提交专家审核”的成功状态。

### 画面节奏与特写

- 先显示处理前数据，再逐项录入恢复值，形成明显的前后对比；
- 最终原因、实际处理和恢复结果各保留一行核心内容；
- 提交按钮点击后不得立刻剪切，要完整显示成功状态和流转去向；
- 使用“提交专家审核”作为从工程师端过渡到后续专家端的伏笔。

### 固定结果

- 最终原因：滤网积尘造成风道阻塞，同时风扇老化导致转速持续偏低；
- 实际处理：清理滤网与风道，更换老化风扇，并核对 FAN1/FAN2 接线；
- 恢复结果：温度和风扇转速恢复正常，连续观察 15 分钟无新增告警；
- 遗留风险：无。

### 口播

> 处理完成后，工程师录入恢复参数和实际检修结果。风扇转速恢复至每分钟一千二百八十转，系统与 CPU 温度回落，连续观察十五分钟无新增告警。该结果随后进入专家审核流程。

### 画面验收

- 处理前后的参数变化清晰；
- 最终原因、处理措施、恢复结果均有内容；
- 成功提交状态完整出现。

## 镜头 09：检修记录与两页 PDF 作业卡

**时间：03:35—04:00**

### 画面操作

1. 打开“检修记录”；
2. 展示列表中不同型号、不同故障的多条记录；
3. 打开本次散热异常记录；
4. 点击“打印作业卡”；
5. 在打印预览中快速展示：
   - 第 1 页：任务摘要、风险与检修结论；
   - 第 2 页：恢复参数、签字确认和追溯信息；
6. 关闭打印预览并返回系统。

### 画面节奏与特写

- 检修记录列表先展示整体数量，再将当前案例高亮；
- 打印预览用连续滚动依次展示第 1 页和第 2 页，不快速来回翻页；
- 对任务摘要、恢复参数和签字区域各做一次短暂放大；

## 5. 两个固定检修问答

### 5.1 问题一：这个接线顺序是怎么样的？

回答画面应至少体现以下内容：

1. 先停机断电，执行安全隔离，并确认风扇完全停转；
2. 对照主板或监控模块丝印确认 FAN1、FAN2 接口，禁止仅凭线束位置判断；
3. 核对原有线束标识和插头防呆方向，逐一确认 FAN1 后再确认 FAN2；
4. 检查插头是否完全插入、卡扣是否到位、线束是否受挤压或松动；
5. 恢复供电后分别核对风扇运行、转速反馈和 TEMP/FAN 告警状态；
6. 如果现场型号、接口标识或线序与资料不一致，应停止操作并按对应型号手册或专家意见确认。

### 5.2 问题二：风扇转速偏低可能由哪些情况导致？

回答画面应至少体现以下内容：

1. 滤网积尘或异物堵塞造成进风受阻；
2. 风道受阻、机柜空间不足或线束遮挡；
3. FAN1/FAN2 接线错误、插头松动或接触不良；
4. 风扇供电电压不足或电源回路异常；
5. 风扇轴承磨损、叶片卡滞或风扇老化；
6. 转速反馈线、监控接口或采集模块异常；
7. 智能温控策略、阈值或控制参数配置异常。

3. 密码重置成功提示不得展示固定密码 `123456`，建议显示“密码已重置，请通知用户使用一次性凭据”；
4. 账号停用操作建议有确认提示，防止误触；
5. 所有页面中的设备位置、案例编号、知识编号和版本号保持一致；
6. 对外画面不出现“模拟回答”“后续接入”“预留功能”“MVP”等开发状态文字；
7. 不要让鼠标长时间停在可能显示“演示”字样的提示气泡上。

这些项目只影响正式录制呈现，不改变脚本中的业务流程。

## 8. 拍摄方法

### 8.1 推荐方式

采用“分镜录屏 + 后期配音”，不要尝试一次连续完成全部七分钟。

1. 按 17 个镜头分别录制，每个镜头前后多留 2 秒；
2. 每个关键操作至少录制两遍；
3. 后期按时间表剪辑，删除等待和误操作；
4. 页面加载和角色切换可以加速，但提交、发布、命中和状态变化不能被剪掉；
5. 口播单独录音后与画面对齐，避免边操作边说造成节奏失控；
6. 最终统一添加字幕、章节角标和必要的局部放大。

### 8.2 局部放大建议

只在以下位置使用局部放大：

- 风扇转速和温度阈值；
- 检修智能体的两个回答；
- PDF 的页数和关键栏目；
- 知识图谱“本次新增与修改”；
- `KB-008` 的 V1.0 → V1.1；
- “成功命中新知识”；
- 管理员账号维护结果。

其他位置保持全页面，避免频繁缩放造成眩晕。

### 8.3 字幕规则

- 每行不超过 24 个汉字，最多两行；
- 字幕置于底部安全区，不遮挡页面主按钮；
- 功能名称使用界面中的正式名称；
- 数值和单位统一，例如 `420 rpm`、`58℃`、`15 分钟`；
- 章节角标只保留“现场接入、智能诊断、检修执行、知识回流、后台管理”五类。

## 9. 故障预案

| 风险 | 录制前处理 | 现场替代方案 |
| --- | --- | --- |
| 语音识别失败 | 提前授权并在安静环境试录 | 保留一次成功录屏素材，必要时使用该镜头替换 |
| 文件上传窗口暴露个人信息 | 素材放入独立目录并使用简短文件名 | 只截取点击上传后的页面状态 |
| 多智能体动画等待过长 | 提前完整运行一次，确保资源已缓存 | 后期将等待段加速，不剪掉结果出现过程 |
| 打印窗口录不到 | 使用显示器采集而非单窗口采集 | 预先导出 PDF，用浏览器打开后展示两页 |
| 图谱节点加载失败 | 录制前依次打开两种视图 | 重新加载后单独补录图谱镜头 |
| 专家发布后无法命中 | 录制前从 V1.0 完整预演到 V1.1 | 重置数据后重新录制镜头 13、14 |
| 用户管理页面信息过密 | 提前调整浏览器缩放，确保统计、筛选和用户列表同屏 | 保持单页不操作，只对页面区域做轻微推镜 |
| 角色状态串联错误 | 每个角色录制前确认当前案例状态 | 三个角色分别录制，再通过转场连接 |
| 七分钟超时 | 每段按时间表硬切 | 优先压缩页面切换，不删除主闭环状态变化 |
