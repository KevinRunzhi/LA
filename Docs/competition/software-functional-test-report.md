## 编写与执行边界

1. 需求、设计和产品说明书用于确定应具备的产品能力；实际测试必须以冻结的参赛安装包和对应源代码提交为对象。
2. 当前可运行代码主要采用 React 与 Flask，正式文档描述的是最终交付形态及其目标技术架构。最终测试报告应如实记录安装包的真实实现，不以目标架构替代实测环境。
3. 本轮功能测试以当前可运行版本和固定演示数据为对象；文档分支基线为 `Docs@85bca15`，主分支参考基线为 `main@91951de`。最终交付包形成后仍需补充安装包文件名和 SHA-256，以完成交付物级追溯。
4. 已执行项目按实际功能表现判定；尚不具备目标硬件、原生组件或持续压测条件的项目统一标记为“待测试”，不计入已通过范围。
6. “散热异常”作为唯一完整展开的典型业务闭环。其他设备、品牌和故障领域通过知识库、手册、案例、检索与知识图谱覆盖性用例验证，不复制同等深度的完整闭环。
7. LoongArch64、银河麒麟 V10、Neo4j 原生部署、全离线安装和长时间性能稳定性结论必须来自对应真实环境，本报告不以参考环境结果替代，因此相关项目保留待测试状态。

## 1. 引言

### 1.1 编写目的

说明本报告用于验证软件功能是否满足需求分析、功能设计、产品说明和比赛交付要求，并为评审提供可追溯的测试过程、实际结果、缺陷记录和证据索引。

### 1.2 测试目标

- 验证工程师、专家和用户管理员的主要功能与权限边界；
- 验证从异常接入到知识回流的核心业务闭环；
- 验证文本、语音、图片、视频和音频等多模态输入及其异常处理；
- 验证知识库、检修手册、案例与知识图谱的检索、展示、审核和发布；
- 验证检修记录及两页 A4 作业卡 PDF 的内容、版式和可归档性；
- 验证兼容性、性能、稳定性、安全性、部署与可维护性要求；
- 识别目标功能、实际安装包和运行环境之间的差异并形成缺陷或风险记录。

### 1.3 适用范围

本报告适用于最终参赛交付版本的功能测试、业务流程测试、接口辅助验证、专项测试、回归测试和交付验收，不替代源代码级单元测试报告或第三方安全测评报告。

### 1.4 术语与缩略语

列出检修任务、异常事件、检修资料包、知识条目、图谱变更集、作业卡、SUT、SSE、RAG、ASR、OCR、PDF 等术语，统一沿用需求分析和功能设计文档中的定义。

## 2. 被测软件概述

### 2.1 软件名称与定位

概述“工控设备智能检修与知识作业系统”的产品定位、适用角色、适用设备范围与工业现场应用价值。

### 2.2 被测功能组成

按以下功能域描述被测范围：

1. 公共能力与身份访问；
2. 工程师工作台与异常接入；
3. 设备、故障和检修资料确认；
4. 知识检索、智能诊断与检修预方案；
5. 标准化检修向导、当前步骤问答与专家协同；
6. 恢复验证、检修记录和作业卡；
7. 专家审核、知识修正、退回、归档与发布；
8. 检修知识库、手册、案例与知识图谱；
9. 用户管理后台与系统设置；
10. 部署、运维与非功能能力。

### 2.3 核心业务链路

`工业现场异常接入 → 设备与故障识别 → 检修资料与知识检索 → 智能辅助诊断 → 步骤化检修 → 专家审核 → 检修记录与作业卡输出 → 案例、知识和图谱回流`

## 5. 测试方法、级别与通过准则

### 5.1 测试级别

- 构建验收测试：确认安装包可校验、安装、启动并完成最小主路径；
- 系统功能测试：按功能域验证正常、边界和异常路径；
- 业务流程测试：跨角色、跨模块验证数据与状态闭环；
- 专项测试：验证兼容性、性能、稳定性、安全性、PDF 和部署；
- 回归测试：重要修复或构建变更后按影响范围复测。

### 5.2 测试方法

采用黑盒功能测试为主，结合等价类、边界值、错误推测、状态迁移、场景法、权限矩阵、接口响应检查、日志核对、导出文件检查和跨存储一致性检查。

### 5.3 用例执行状态

| 状态 | 定义 |
| --- | --- |
| 通过 | 实际结果符合全部预期，证据完整 |
| 失败 | 实际结果与一项或多项预期不符 |
| 待测试 | 因目标硬件、原生组件或持续压测条件暂不具备，留待对应环境验证 |
| 不适用 | 经评审确认不属于该冻结版本或环境，必须说明依据 |

### 5.4 缺陷级别

| 级别 | 判定原则 |
| --- | --- |
| 致命 | 无法安装、无法启动、数据不可恢复，或核心业务整体不可用 |
| 严重 | 核心流程、权限隔离、数据一致性或关键交付物不可用，且无可接受规避方案 |
| 一般 | 局部功能错误或主要体验受损，但有规避方式且不阻断核心流程 |
| 轻微 | 文案、样式、提示或低影响一致性问题 |

### 5.5 进入准则

1. 被测提交和安装包冻结，可通过校验值唯一识别；
2. 部署步骤、测试账号和基础测试数据可用；
3. 需求、设计、产品说明与版本差异已评审；
4. 目标环境或经批准的阶段环境已准备；
5. 用例、预期结果和证据目录已评审。

### 5.6 退出与通过准则

1. 核心业务闭环和关键角色权限用例全部执行且通过；
2. 所有测试内容均有明确结论，待测试项目单独列示且不计入通过；
3. 不存在未关闭的致命或严重缺陷；
4. 一般和轻微遗留缺陷已评估影响、规避措施和交付风险；
5. 目标平台专项如尚未具备测试条件，必须明确列为待测试并说明适用边界；
6. PDF、日志、截图、接口响应和环境证据可从用例反向追溯；
7. 已执行项目以通过、失败统计，待测试和不适用项目单独列示；
8. 最终结论只覆盖实际执行过的被测版本、环境和范围。

- P0：构建启动、登录权限、散热异常核心闭环、专家审核发布、数据一致性和作业卡；

优先级只决定执行顺序，不改变是否纳入最终统计。

## C.4 专家退回与重新提交

1. 工程师提交缺少观察时间或恢复依据的记录；
2. 专家检查材料，填写退回原因和指定补充项；
3. 系统将任务转为可补充状态，同时保持原提交版本；
4. 工程师补充恢复数据并重新提交；
5. 专家查看前后差异，继续审核；
6. 验证退回记录、补充人员、时间、版本和最终决定完整可追溯。

预期结果：退回不会删除原始事实和审核草稿；重新提交生成新版本；旧版本不会被新值无痕覆盖；未再次通过前不产生正式知识。

## C.5 仅归档案例

1. 提交一条事实完整但不具有新增知识价值的案例；
2. 专家选择“仅归档案例”并填写原因；
3. 确认案例进入历史查询；
4. 查询知识版本和图谱变更；
5. 使用相似异常检索。

预期结果：案例可查且来源完整；不产生新的知识版本和图谱关系；相似异常不会错误宣称命中新发布知识。

## C.6 发布失败与恢复

1. 在知识发布前保存专家审核结果；
2. 模拟知识写入、图谱写入或索引更新失败；
3. 检查上一正式版本和当前候选状态；
4. 恢复依赖后重试同一发布请求；
5. 检查版本、关系和审计数量。

预期结果：上一正式版本持续可用；失败批次不标记已发布；审核结论不丢失；重试幂等，不产生重复版本、重复关系或重复案例。
