# 工控设备智能检修与知识作业系统

# 软件安装包及部署文档 Spec

> 实现状态：本Spec规定的第1—9批文档内容已全部落地，尚待最终安装包和目标机验证才能关闭的项目集中记录在正式文档附录L。

## 1. Spec 目的

本 Spec 用于约束《软件安装包及部署文档》的分批编写、事实边界、技术口径和验收标准。正式文档必须能够指导部署人员在 LoongArch64、银河麒麟 V10 系列目标环境中，使用随包离线资源完成目标架构软件的安装、配置、初始化、启动、验收、维护、备份、升级、回退和卸载。

本 Spec 是文档编写和审阅依据，不替代最终部署文档，不包含比赛现场才可回填的执行结果。

## 2. 文档目标

正式文档完成后应满足以下目标：

1. 部署人员无需研发人员口头补充即可理解交付物、部署拓扑和组件依赖。
2. 能够在禁止访问外部系统软件源的条件下完成目标架构离线安装。
3. 能够部署并验证 Vue 3 前端、Nginx、FastAPI/Uvicorn、Celery、PostgreSQL/pgvector、Redis、Neo4j、文件资源库、PDF与音视频处理、Prometheus/Grafana和systemd服务。
4. 能够配置统一模型网关，并按最终方案连接千问语言、OCR、ASR、向量化和重排序能力。
5. 能够初始化业务数据库、知识库、向量索引、图谱和文件资源，并验证跨存储一致性。
6. 能够完成三类角色、散热异常核心闭环、智能能力、作业卡、监控和重启持久化验收。
7. 能够执行日常检查、备份恢复、升级回退、故障诊断和安全卸载。
8. 所有高风险操作均具有明确目标、前置备份、失败保护和验证步骤。

## 3. 目标架构范围

### 3.1 随包交付组件

正式离线安装介质应包含以下组件或其可离线安装资源：

| 技术层级 | 目标组件 | 部署文档必须覆盖的内容 |
| --- | --- | --- |
| 前端 | Vue 3、TypeScript、Vite生产构建 | 静态资源部署、公开运行配置、浏览器访问 |
| 统一入口 | Nginx | 静态托管、API/SSE代理、TLS、安全控制 |
| 核心后端 | Python 3.12、FastAPI、Uvicorn | 离线依赖、配置、systemd、健康检查 |
| 异步任务 | Celery | 队列、并发、超时、重试、失败恢复 |
| 业务数据库 | PostgreSQL | 安装、账号、配置、迁移、备份恢复 |
| 向量检索 | pgvector | 扩展安装、1024维向量、索引和检索验证 |
| 缓存与消息 | Redis | 监听、认证、队列、内存和持久化策略 |
| 图数据库 | Neo4j | 原生或独立节点安装、Bolt、初始化、备份恢复 |
| 文件资源 | 本地受控文件资源库 | 目录、权限、校验、备份和清理 |
| 文档与媒体 | 文档解析依赖、FFmpeg | 离线依赖、格式处理和能力验证 |
| PDF | Jinja2、WeasyPrint、思源字体 | 字体、模板、两页A4作业卡验证 |
| 模型接入 | 统一模型网关及模型客户端 | 配置、密钥、连通性、超时、重试、降级 |
| 监控 | Prometheus、Grafana | 指标、数据源、仪表盘、告警和systemd |
| 服务管理 | systemd | 依赖、启停、重启、状态和开机自启 |

### 3.2 模型服务边界

统一模型网关、适配器、配置模板和检查工具属于随包部署内容。千问模型 API 或独立模型推理节点属于外部或独立能力节点，正文必须说明网络、鉴权、超时、重试和降级，不得描述为业务节点本地已安装的模型权重。

### 3.3 Neo4j 部署边界

Neo4j 必须纳入正式系统。正文同时保留以下部署配置：

- 配置 A：在 LoongArch64 业务节点原生部署；
- 配置 B：在独立兼容节点部署，由业务节点通过受控 Bolt 连接。

最终推荐配置由 LoongArch64、银河麒麟和固定 Neo4j 版本专项验证决定。在验证完成前不得把原生运行表述为已确认事实。

### 3.4 非目标范围

以下内容不作为正式部署正文的主路径：

- 当前 React、Flask、SQLite/JSON 演示包；
- Vite热更新、源码调试和开发态启动；
- Docker或Kubernetes部署；
- 公网高并发生产集群；
- 未经比赛目标环境确认的第三方托管服务。

## 4. 来源与优先级

文档内容按以下优先级确定：

1. 用户在当前会话中确认的目标架构随包部署要求；
2. 《目标技术架构基线》；
3. 《软件功能设计文档》；
4. 《软件功能需求分析文档》；
5. 《软件产品说明书》；
6. 《软件功能测试报告》；
7. 最终安装包、部署脚本和目标机真实验证结果；
8. 固定版本组件的官方文档。

当设计文档与最终安装包不一致时，必须确认差异并同步修正文档或安装包，不允许在部署文档中隐去差异。

## 5. 正式文档结构要求

## 6. 内容表达规范

### 6.1 操作步骤

每组正式操作至少包含：

- 操作目的；
- 前置条件；
- 执行账号；
- 执行节点；
- 命令或配置；
- 预期结果；
- 失败处理；
- 完成后验证。

### 6.2 参数与占位符

命令中的可变内容统一使用尖括号占位符，例如：

- `<release-package>`；
- `<install-root>`；
- `<data-root>`；
- `<backup-id>`；
- `<business-node-ip>`；
- `<neo4j-node-ip>`；
- `<model-gateway-url>`。

正式版本冻结后，将应固定的占位符回填到集中参数表；不在正文多个位置分别写不同默认值。

### 6.3 状态词

| 状态 | 使用条件 |
| --- | --- |
| 已确定 | 已由目标架构或用户明确确认 |
| 待冻结 | 技术方向已确定，但版本、数值或文件名需在最终包形成后固定 |
| 待验证 | 必须经过目标机或外部节点专项验证 |
| 可选 | 由最终部署拓扑或现场策略决定 |
| 不适用 | 经评审确认不属于最终交付版本 |

不得使用“应该可以”“理论上支持”“大概”等模糊表述代替状态说明。

### 6.4 命令安全

- 不使用宽泛的递归删除命令；
- 不使用 `pkill python`、`killall` 等无法限定本系统进程的命令；
- 不使用 `chmod -R 777`；
- 不使用未解析的环境变量作为删除、移动或覆盖目标；
- 迁移、恢复、升级和卸载前必须解析并显示目标路径；
- 服务操作优先通过本系统 systemd 单元或维护脚本执行。

### 6.5 秘密与敏感信息

数据库密码、JWT签名材料、会话密钥、模型API密钥和文件加密密钥不得出现在代码、前端构建、普通配置模板、命令历史示例或日志示例中。正文只说明生成、注入、权限、轮换和检查方式。

## 7. 统一参数冻结要求

以下参数必须由一个集中参数表管理，并在最终定稿前冻结：

- 安装包名、版本、构建号和SHA-256；
- 所有组件固定版本及LoongArch64安装来源；
- 节点数量、节点角色和地址；
- 安装、配置、数据、文件、日志和备份目录；
- systemd服务名、运行账号和启动依赖；
- 端口、监听地址和防火墙规则；
- 数据库、图数据库、Redis和模型网关连接参数；
- Celery队列、并发、超时和重试；
- 硬件最低配置、推荐配置和容量指标；
- 备份周期、保留周期、RPO和RTO；
- TLS、JWT、Cookie、CSRF和会话配置。

## 8. 分批实现与验收

| 批次 | 完成范围 | Spec 验收点 |
| --- | --- | --- |
| 第1批 | 文档基线、引言、交付物、总体部署方案 | 目标组件齐全；节点、边界和依赖清楚 |
| 第2批 | 包目录、环境、目录、端口、账号和参数 | 所有参数有统一来源；无前后冲突 |
| 第3批 | 准备、校验、解压、基础组件离线安装 | 不访问外部软件源；组件失败可定位 |
| 第4批 | 前端、后端、Celery、模型、监控、安全和秘密 | 最小权限；秘密不泄露；入口统一 |
| 第5批 | PostgreSQL、知识、向量、图谱、文件初始化和服务编排 | 初始化顺序正确；跨存储一致；可判断就绪 |
| 第6批 | 部署验收、核心闭环、监控和日常维护 | 全组件和业务均验收；证据可追溯 |
| 第7批 | 备份恢复、升级回退 | 备份可恢复；跨存储同批次回退 |
| 第8批 | 故障处理、卸载和清理 | 无危险泛化命令；保留项明确 |
| 第9批 | 附录、实机验证、版本回填和全篇校对 | 命令、版本、目录、端口、结果与安装包一致 |

## 9. 每批质量检查

每批完成后至少检查：

1. 是否只使用统一的软件名称和目标平台名称；
2. 是否遗漏目标架构组件；
3. 是否把外部模型服务误写成随业务节点安装；
4. 是否对Neo4j部署位置作出未经验证的结论；
5. 是否出现互相冲突的目录、端口、账号、服务名或启动顺序；
6. 是否存在秘密、生产口令或真实个人路径；
7. 是否存在不可恢复的覆盖、删除和进程操作；
8. 是否为失败路径提供了判断和处理；
9. 是否与其他四份比赛文档保持功能与技术口径一致；
10. Markdown标题、表格、代码块和内部引用是否完整。

## 10. 最终验收标准

正式文档只有在以下条件全部满足时方可定稿：

- 18章正文和全部附录完整；
- 目标架构全部随包组件均有安装、配置、初始化、启停和验证说明；
- 完整离线安装在LoongArch64、银河麒麟目标环境验证；
- Neo4j最终部署拓扑和固定版本已确认；
- 安装包、组件、数据库模式、知识和图谱版本可追溯；
- 三类角色和散热异常完整闭环在部署后验收通过；
- 备份恢复和升级回退经过实际演练；
- 正式命令、目录、端口、服务名、配置键和预期输出经过校对；
- 安装包名称、SHA-256和测试报告中的被测对象一致；
- 所有待冻结、待验证和可选项已关闭或在最终限制中明确说明。
