# 阶段 A：基线冻结与迁移准备 Spec

> 状态：未开始
> 前置依赖：无
> 阶段结果：得到可比较、可迁移、可回滚的当前系统基线

## 1. 目标

在修改架构前确认当前代码、数据库和演示链路的真实状态。阶段 A 不开发新案例功能，只建立后续重构必须依赖的事实和保护网。

## 2. 非目标

- 不创建供电页面；
- 不修改散热业务内容；
- 不调整现有界面视觉；
- 不迁移数据库结构；
- 不引入新依赖；
- 不更新功能状态为“已完成”。

## 3. 开始条件

- 当前分支为 `feature/industrial-computer-power-fault`；
- Spec 提交 `4ff7aed` 和确认项提交 `40da7da` 可见；
- 工作区中的用户文件已识别；
- WSL Node、npm 和 Python 可用。

## 4. 基线调查范围

### 4.1 代码入口

记录：

- React 应用入口和主要页面组件；
- 当前案例、诊断、向导、记录、PDF、专家、图谱和同步状态所在文件；
- Flask 启动入口、蓝图和数据存储层；
- SQLite 初始化、重置和发布逻辑；
- JSON 数据文件和静态素材目录；
- 当前测试命令、构建命令和启动端口。

### 4.2 数据库

对当前 `presentation.db` 生成只读清单：

- 表、索引和触发器；
- 每张核心表的记录数；
- 案例、知识版本、图谱和同步记录；
- `presentation_state` payload 的结构；
- 初始化和 reset 对现有数据的实际影响。

不得把数据库文件或包含个人信息的导出纳入 Git。

### 4.3 散热完整链路

建立基线步骤：

```text
首页输入
→ 动态接诊
→ 多 Agent 会诊
→ 检修预方案
→ 检修向导
→ 步骤问答
→ 检修完成记录
→ 作业卡
→ 工程师上传
→ 专家审核与发布
→ 图谱变化
→ 工程师同步
```

每一步记录：

- 进入条件；
- 当前页面标题和关键数据；
- 关键按钮；
- 后端请求；
- SQLite 状态变化；
- 当前已知缺陷。

## 5. 硬编码清单

使用搜索和人工复核建立迁移矩阵，至少查找：

```text
CASE-ACP4000-001
KB-008
TEMP/FAN
FAN1
FAN2
fanSpeedRpm
systemTemperatureC
cpuTemperatureC
ACP-4000
IPC-610
```

清单字段：

| 字段 | 说明 |
| --- | --- |
| 文件与行号 | 当前硬编码位置 |
| 业务表面 | 接诊、诊断、向导、PDF、专家或图谱 |
| 数据类型 | 身份、文案、规则、状态或视觉 |
| 迁移目标 | CasePackage、CaseRun、共享知识或兼容层 |
| 风险 | 高、中、低 |
| 阶段 | B、C、D 或 E |

## 6. 可信度审计

重点审计散热案例当前 `verified_case`：

- 是否存在真实检修记录；
- 是否有处理前后照片或测量；
- 是否只有演示预设值；
- 官方手册能证明哪些事实；
- 专家审核能证明哪些事实；
- 哪些关系只能保留为未核验经验。

输出审计结论，不在阶段 A 直接改数据。没有证据时后续必须采用更准确的内部可信等级。

## 7. 基线验证

### 7.1 自动检查

- 当前前端生产构建；
- 当前后端测试或 Python 编译检查；
- Flask 健康检查；
- 主要演示 API 响应；
- 当前数据库可读取。

### 7.2 浏览器检查

至少完整走一次散热主路径，重点保存：

- 首页和接诊；
- 诊断结论；
- 预方案及编辑；
- “检查滤网、风扇和接线”步骤；
- FAN1/FAN2 接线问答；
- 检修记录和 PDF；
- 专家审核；
- 图谱当前视图和本次变化；
- 工程师同步。

### 7.3 基线产物

建议保存到不提交真实运行数据的审计目录：

```text
output/case-platform-baseline/
├── environment.txt
├── database-summary.json
├── api-results/
├── screenshots/
└── browser-checklist.md
```

只将无敏感信息且适合长期保存的摘要纳入 Git。

## 8. 风险与处理

| 风险 | 处理 |
| --- | --- |
| 工作区已有修改 | 不覆盖，先划定范围 |
| 数据库状态已被演示污染 | 备份并记录，不直接重置 |
| 当前主路径本身有缺陷 | 记录为基线缺陷，判断是否阻断迁移 |
| 文档与代码不一致 | 以代码和实际运行结果为准，并记录差异 |

## 9. 阶段门禁

全部满足后才能进入阶段 B：

- 当前结构和启动方式清楚；
- 散热主路径可重复或已记录明确阻断项；
- 数据库已备份并有结构摘要；
- 硬编码迁移矩阵完成；
- 可信度审计有结论；
- 当前构建和关键 API 结果已保存；
- 没有修改业务行为。
