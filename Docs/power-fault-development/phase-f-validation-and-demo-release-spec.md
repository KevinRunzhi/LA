# 阶段 F：综合验收与演示发布 Spec

> 状态：未开始
> 前置依赖：阶段 E 门禁通过
> 阶段结果：证明架构可扩展，并形成可直接演示的稳定版本

## 1. 目标

通过第三个最小测试案例、双案例完整回归、数据库迁移演练、WSL 和龙芯验证，证明这不是只为散热与供电写的双案例分支，并冻结可重复演示版本。

## 2. 非目标

- 不新增第三个正式演示故障；
- 不继续扩张 UI 功能；
- 不在验收阶段重构架构；
- 不更换技术栈；
- 不用人工解释替代失败的自动化检查。

## 3. 第三个最小测试案例

案例 ID：

```text
CASE-FIXTURE-003
```

用途仅为测试，不进入正式演示候选。内容选择一个与散热和供电字段不同的最小故障，例如 RTC 电池异常。

必须包含：

- 独立 intake 字段；
- 至少两个诊断方向；
- 三个向导步骤；
- 一个步骤问答主题；
- 两个工程师结果指标；
- 一个知识候选；
- 两个图谱候选关系。

验收条件：

- 只增加注册表测试项和案例包；
- 不修改 React 业务组件；
- 不新增 caseId if/else；
- 通用加载、路由测试、向导、记录和专家列表可识别；
- 正式页面默认不展示该 fixture。

## 6. 视觉验收

重点检查：

- 首页主线仍清楚；
- 明确命中后无多余确认页；
- 页面通用名称正确；
- 两个案例字段不会同时铺开；
- 当前步骤问答文字清晰；
- 图谱聚焦和缩放流畅；
- “本次新增与修改”只显示选中版本；
- PDF 两页无截断、遮挡或异常分页；
- 1280×720 主演示视口无关键操作被折叠；
- 浏览器控制台无阻断性错误。

## 7. 性能和稳定性

记录而非主观判断：

- 首页到命中跳转耗时；
- CasePackage 首次加载耗时；
- CaseRun 恢复耗时；
- 图谱渲染耗时；
- PDF 生成耗时；
- 连续重走两次完整链路的稳定性；
- 后端重启后的状态恢复。

本阶段不追求生产级性能，但主演示动作不能出现明显空白、卡死或不可解释等待。

## 8. 演示数据库冻结

准备可重复演示的数据状态：

- 基础手册和知识存在；
- 散热基线知识存在；
- 供电知识处于演示需要的初始版本；
- 没有残留待审核 run 干扰；
- 图谱基线正确；
- 演示账号可用；
- “重新开始”会创建新 run；
- 已发布资产不会被重置。

记录：

```text
database schema version
seed version
registry version
case package versions and hashes
frontend build commit
backend commit
reset procedure
```

数据库本体是否提交按现有仓库规则决定；不能提交时提供幂等生成或恢复步骤。

## 10. 演示脚本

最终演示建议主讲供电，散热作为已有能力和回归证明：

```text
输入供电异常
→ 自动命中并跳转
→ 查看供电证据链
→ 确认检修预方案
→ 分段测量
→ 询问接线和安全
→ 修复并验证
→ 打印两页作业卡
→ 专家发布 V1.1
→ 图谱显示本次变化
→ 工程师同步
```

准备兜底：

- 标准输入文本；
- 干净的新 run；
- 浏览器书签或固定入口；
- 已生成 PDF；
- 发布前数据库备份；
- 服务重启命令；
- 未支持故障的正确说明。

## 11. 缺陷分级

| 级别 | 定义 | 发布处理 |
| --- | --- | --- |
| P0 | 主路径中断、数据覆盖、发布错误、安全规则可绕过 | 必须修复 |
| P1 | 关键内容错误、PDF 不可用、跨案例串数据、图谱版本错误 | 必须修复 |
| P2 | 次要布局、非关键动画或提示问题 | 评估后记录 |
| P3 | 不影响演示的优化建议 | 后续处理 |

P0/P1 未清零不得冻结演示版本。
